Our stream setup had grown into a monster: a dozen OBS scenes, browser sources
pointing at HTML files nobody remembered writing, and a wall of hotkeys only
one person knew. Changing anything meant clicking through nested menus and
hoping we didn't break the layout before going live.

## The whole layout is now code

We rebuilt it in Smelter. The camera, the screen capture, and the alert overlay
are inputs; the scene is a component tree that describes where each one goes.
Switching "scenes" is switching which component renders — a state change, not a
click through a menu.

It came out to about forty lines. We can read the entire layout on one screen,
diff it in a pull request, and roll back a change that looked bad on stream.

## What changed for us

- The layout lives in git, so every change is reviewable and reversible.
- Anyone on the team can understand the setup by reading it, not by clicking.
- Local rehearsal and the live stream run the exact same code.

It's not that OBS couldn't do it — it's that we finally have a setup we can
reason about, and that's made experimenting on stream fun again.
